# Domain Docs

## Before exploring

Read the root `CONTEXT.md` if it exists, and read relevant decisions in `docs/adr/`. If either is absent, proceed silently; domain-modeling skills create them when terms or decisions are resolved.

## Layout

This is a single-context repo:

- `/CONTEXT.md` — domain glossary and concepts
- `/docs/adr/` — architecture decision records

Use the glossary's vocabulary in issues, proposals, hypotheses, and test names. If a concept is missing, note the gap for domain modeling. If work conflicts with an ADR, surface the conflict instead of silently overriding it.
